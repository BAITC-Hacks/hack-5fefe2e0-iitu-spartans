# AGENTS.md — правила работы над проектом (читать перед любым коммитом)

Это командный репозиторий хакатона **HackAlem AI 2026** (Astana Hub · BAITC · powered by OpenAI).
Организаторы — владельцы репо, проекты **судит AI-скоринг + жюри**, история коммитов проверяется.
Ниже — жёсткие правила из официального Положения. Нарушение = дисквалификация всей команды.

## Красные линии (нельзя — дисквалификация, раздел 12 Положения)
- **НЕ коммитить готовое решение до старта.** Работа над конкурсным проектом ведётся ТОЛЬКО в этом репо и ТОЛЬКО с 23.09 (п.6.8). До старта допустим лишь нейтральный каркас (структура, окружение, пустой README) и это надо честно раскрыть (п.6.4).
- **НЕ подделывать историю коммитов.** Судьи смотрят историю разработки, метаданные файлов, фактический вклад каждого (п.6.5, 8.6). Фальш-история = дисквал.
- **Почасовой прогресс (п.6.6):** с начала соревнования КАЖДЫЙ час нужен реальный промежуточный результат (коммит, функционал, прототип, схема, тест, данные). Нет прогресса за час = основание для дисквалификации.
- **Codex обязателен** в процессе разработки (требование хакатона). Использование Codex должно быть видно по ходу работы.
- **Проект должен быть развёрнут и доступен** (п.8.7–8.9): рабочий деплой + активная ссылка + доступ для проверки. Не запускается = отклонён.
- **Все 3 участника офлайн на площадке 23.09** (EXPO, Астана), check-in по личному QR, QR не передавать, площадку не покидать без разрешения (п.3.7, 4.6).
- **Раскрыть любой ранее созданный код, библиотеки, модели, датасеты, шаблоны** (п.6.4).

## Как работать (вывод из правил)
1. До 23.09 — только каркас проекта и репетиция локально. Кейс трека выдаётся в момент старта.
2. С 23.09 — код только сюда, коммиты часто и честно, каждый час виден прогресс.
3. Через Codex, с рабочим деплоем и сильным README (README = отдельные баллы + основа оценки).
4. Автор коммитов — участники команды. Без служебных подписей сторонних инструментов.

## Что своё можно приносить (собственные наработки, скиллы, архитектура)
Разрешено, но по правилам Положения:
- **Свои инструменты, шаблоны архитектуры, библиотеки, датасеты, каркасы — можно** использовать. Условие п.6.4: честно РАСКРЫТЬ в README, что это ранее созданный материал («использованы собственные наработки: …»).
- **Заранее (до 23.09) в этом репо — только нейтральный каркас** (структура, окружение, Docker, пустой README). Готовое решение под кейс заранее НЕЛЬЗЯ — кейс выдаётся на старте (п.6.8).
- **Свои модули/заготовки держать в СВОём репо**, а сюда подключать как заявленную зависимость на площадке. Не приносить готовый проект и не пушить одним коммитом (фальш-история = дисквал, разд.12).
- **Работа над конкурсным решением — только здесь и только с 23.09**, с реальным почасовым прогрессом (п.6.6).
Коротко: свой арсенал использовать МОЖНО, но раскрыть источник и строить историю коммитов честно на площадке.
