### 1. Анализ ТЗ и выбор кейса

**Рассмотрено:** различие внутреннего контура Career Quest и внешнего контура Voice Router. Для дальнейшей работы выбран только второй кейс.

**Результат:** определён основной процесс:

```text
Клиент → STT → текст и контекст → LLM Router → политика решения
       → сценарий / уточнение / передача оператору
       → при необходимости Mock Backend → текст ответа → TTS

Результаты этапов → панель трассировки
```

Зафиксированы требования: выбор из 40 сценариев с помощью LLM, диалог до 10 реплик, русский и казахский со смешением языков, голосовой ввод и ответ, объяснение выбора и замеры по этапам. Ориентиры скорости — 500 мс на маршрутизацию и 1,5 секунды до начала ответа; достижение этих ориентиров не является условием сдачи.[^tz]

**Риски:** потратить основное время на голосовую оболочку вместо маршрутизации; пропустить контекст, смену темы или пограничные запросы.

**Артефакт:** предварительная аналитика `docs/ANALYSIS.md`.[^analysis]

**Рассмотрено:** README набора и показанный код `evaluate.py`. Данные относятся к вымышленной страховой компании **Saqta Insurance**, а не к реальным банковским операциям.[^kit]

| Файл | Назначение / объём |
| --- | --- |

**Результат:** уточнены системные намерения `SYS_OUT_OF_SCOPE`, `SYS_UNCLEAR`, `SYS_GOODBYE`; роль границ `not_this_if`; порядок обработки нескольких намерений — сначала `urgent`, затем остальные в порядке упоминания. Для необратимых действий требуется явное подтверждение. Дата отсчёта внутри набора — **2026-10-01**; она не заменяет дату этого журнала.[^kit]

Изучен формат предсказаний: идентификатор реплики → упорядоченный список сценариев. Скрипт считает `primary_accuracy` — совпадение первого сценария, `full_match` — совпадение множеств сценариев, `intent_recall` — полноту обнаружения намерений на multi-intent репликах. Точность первого сценария и полное совпадение также выводятся по языкам и типам запросов.[^eval]

**Ограничение:** часть больших JSON-diff в выгрузке скрыта. Перечень и объёмы выше взяты из README; полная программная валидация всех исходных файлов не проводилась в рамках этого ревью. `evaluate.py` изучен, но не запускался.

**Следующий шаг:** актуализировать разделы данных и оценки в `ANALYSIS.md`, проверить JSON-файлы и подготовить предсказания для первого прогона.

### 6. Ревью API хода диалога — `860dfc2`

**Рассмотрено:** `POST /api/turn`, загрузка каталога, контракт состояния, формирование ответа и демо-маршрутизатор.

**Что видно в коде команды:** запрос валидируется, затем выполняются выбор сценария, политика решения, построение текста ответа и трассировка. Источник решения зависит от окружения: внешний сервис через `ROUTER_URL`, LLM-маршрутизатор ядра при наличии ключа либо демо без ключа. Состояние возвращается клиенту для следующего запроса; в этом контракте сервер не хранит сессию.[^api]

**Результат ревью:** серверная связка обработки реплики показана в коде. Она не равнозначна подтверждённой готовности полного голосового сценария и исполнения бизнес-действий.

| Наблюдение по представленному коду | Что требуется проверить / доработать |
| --- | --- |
| Демо подбирает сценарий по совпадению слов с примерами | Не представлять этот режим как LLM-маршрутизацию; отдельно проверять основной LLM-путь |
| После политики вызывается `buildReply`; вызов исполнителя бизнес-действий в обработчике не виден | Проверить интеграцию мок-действий, идентификацию клиента и подтверждение операций |
| В `ClientDialogState` нет отдельных полей для накопленных `slots` и отложенных тем | Проверить продолжение диалога, сбор параметров и возврат к прерванному сценарию |
| `replyLanguage("mixed")` возвращает `ru` | Сопоставить с правилом README: отвечать на преобладающем языке клиента |
| Серверный `total` включает обработку запроса и переданный `sttMs`, но не начало воспроизведения TTS | Добавить проверку полного интервала «конец речи клиента → первый звук ответа» |

Эти замечания относятся только к показанным файлам и не означают, что нужные модули отсутствуют во всём репозитории.[^api]

**Проверки:** в описании коммита заявлены `pnpm verify 49/49`, сборка Next.js и живые запросы на русском и казахском. Это сведения автора коммита: самостоятельно проверки не повторялись. Сам отчёт с метриками маршрутизации на 104 репликах в переданных материалах не представлен.[^api]

**Следующий шаг:** прогнать основной LLM-путь на dev-наборе и отдельно проверить диалоги с параметрами, сменой языка, несколькими намерениями и передачей оператору.
