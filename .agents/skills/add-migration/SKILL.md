# Новая миграция

1. Файл `db/migrations/NNN_описание.sql`: следующий свободный номер из трёх цифр, описание строчными латинскими
   буквами через `_`. Запускатель отклоняет имена не по формату и повторные номера.
2. Первая строка — комментарий о назначении; для каждой таблицы и индекса — зачем он (какой запрос обслуживает).
3. Условия поиска ложатся на индекс; большие выборки — с `LIMIT`; JSONB — для хранения и показа, не для поиска.
4. Слитую в `main` миграцию не редактировать: исправление — новой миграцией со следующим номером.
5. Проверка на чистой базе: `docker compose down -v && docker compose up --build` — в логе `миграция применена: NNN_...`,
   `/api/health` показывает новое число миграций.
6. Обновить ER-схему в README (раздел 2.5), если изменилась структура.
